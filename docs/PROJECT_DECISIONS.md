# Реестр действующих решений — 14.11.2026

Реестр фиксирует действующие ограничения; номера не имитируют отсутствующую историю D001–D256.

| Решение | Следствие |
|---|---|
| Сохранить Next.js / Node.js / PostgreSQL / Railway | Сверять функции исходного файла, не переносить проект на Python |
| Один онлайн-магазин | Поставщики — внутренние данные, без панелей магазинов и публичного выбора поставщика |
| Наличная оплата новых заказов | Сервер отклоняет BANK_INVOICE; история старых заказов сохраняется |
| Наценка каждому товару | Денежная арифметика в целых дирамах BigInt, старые снимки цен не пересчитываются |
| Автоматическое КП | Цены берутся из каталога, альтернативы обозначаются, отсутствующие позиции не выдумываются |
| Без суточных квот ИИ | Сохранены ограничения файлов, таймауты и защита от дублей |
| SMS строго по одобренным шаблонам | number-1 / text-1, без ссылок; email использует www и PDF |
| Вход сотрудников: пароль и email-код | TOTP и резервные ключи не возвращать |
| Частичный таджикский интерфейс | Не объявлять полностью переведёнными товары, PDF и юридические документы |
| Отдельные решения после запуска | Рефералы, закупочные заказы и GPS не добавлять без согласования объёма |

Проверки запускаются на изолированной локальной базе с отключёнными внешними отправками. Производственные данные не используются для тестовых заказов.
