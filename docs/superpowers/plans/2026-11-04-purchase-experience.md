# Покупка и личный кабинет — план 4 ноября 2026

**Цель:** переработать checkout, регистрацию, страницу товара и просмотр статуса заказа, сохранив актуальные пользовательские изменения.

**Основа:** существующий Next.js / React, текущие синие токены, Button с восстановленной анимацией, существующие API и серверные проверки. Пользователь поручил приступить к реализации. Резерв исходных файлов: `.data/baseline-purchase-2026-11-04`.

## Ограничения
- Не менять главную, каталог, общие стили, анимации, package.json и вложенное приложение `app/`.
- Стили экранов изолировать в CSS modules; существующий дизайн статуса заказа развить, сохранив транспорт и историю.
- Не менять цены, роли, серверный цикл заказа и основную базу.
- Не выдумывать сроки, тарифы, GPS, оплаченный статус и наличие конкретной машины.

## Работы и проверка
- [x] Checkout: выбор доставки/самовывоза карточками, контакты, адрес, транспорт и время, оплата; читаемый итог со стоимостью позиций из актуального server quote, обработка загрузки/ошибок.
- [x] Авторизация: сохранить API и согласие; дать понятную регистрацию, показ пароля, сохранить next при переключении вход/регистрация, ясные ошибки. Остальные режимы остаются рабочими.
- [x] Товар: явные предложения магазинов, крупное фото, понятная покупка, сумма выбранного количества и ограничения. Сбросить состояние добавления при изменении количества/предложения.
- [x] Статус: текущее действие/следующий шаг, реальные даты этапов из истории, адаптивный состав заказа, доставка и самовывоз, отдельный отменённый статус.
- [x] Проверить types, lint, build, существующие тесты и браузер на 1440/390/360 px с отдельной базой. Не приписывать прежние результаты новой версии.

## Решения по обнаруженным ошибкам
- Необходимое изменение сервера: при создании заказа `audit_log.actor_user_id` должен получать `input.userId`, а не ID строки `customers`. Ошибка воспроизвелась интеграционным тестом и мешала заказам авторизованных покупателей.
- Необходимое дополнение авторизации: перенос гостевой корзины после входа/регистрации. Новая функция блокирует строки в транзакции, объединяет одинаковые предложения, отзывает гостевой доступ; повторный вызов ничего не переносит. Наценка и остатки повторно проверяются существующим серверным расчётом.
- Для checkout имя подставляется из профиля покупателя вместе с телефоном.
- В корне находится отдельный Vite-проект `app/`, из-за которого Next выбирает неверную папку страниц. Он сохранён. Для проверки используются копии исходников в Temp и отдельные базы в `.data/`; файлы настройки запуска пользователя не менялись.
