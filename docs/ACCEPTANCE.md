# Проверки выпуска и локализация

## Постоянные проверки

`npm run lint`, `npm run typecheck`, `npm test` проверяют код, контроль доступа, денежную арифметику и целостность операций.

`npm run build:noenv` затем `npm run test:acceptance` запускают браузерные проверки на production-сборке с отдельной локальной PGlite-базой. Нужен Chromium: `npx playwright install chromium`. Используются только тестовые данные; SMS, email и ИИ отключены. Реальные внешние SMS не отправляются.

Сценарии: внутренние ссылки главной, CSP без unsafe-eval, серьёзные/критические нарушения WCAG через axe, русский/таджикский язык с сохранением cookie и SSR html lang, проверка locale API, карта с выбором точки и подстановкой адреса (тайлы и геокодирование замоканы), загрузка скрипта Turnstile. Последняя проверяет совместимость скрипта с CSP, а не антибот-эффективность или реальную регистрацию.

Визуальные эталоны: Chromium на Windows, 390 и 1440 пикселей. Запуск CI настроен на windows-latest. Изменение эталонов: `npm run test:acceptance -- --update-snapshots`, затем обязательный просмотр PNG. Не обновляйте эталоны только ради зелёного теста. Динамические товарные секции замаскированы; изображение и геометрия первого блока, шапка и основные отступы проверяются.

GitHub Actions `.github/workflows/storefront-acceptance.yml` запускается на push/PR и сохраняет HTML-отчёт и трассы при ошибках. Доступность проверяется автоматически частично; ручная проверка клавиатуры/скринридера и редакторская проверка перевода остаются полезны.

## Деньги и рабочая база

`npm run audit:data` выполняет read-only проверку сумм заказов/КП, оплат, остатков, резервов и защиты истории цен. На рабочей базе не исправляет записи автоматически. Для подключения используйте окружение сервиса с DATABASE_URL. Не размещайте пароль БД в командной строке или отчёте.

Деньги хранятся в дирамах. Точные вычисления — BigInt, дробные количества — в тысячных. Текущая цена товара: целая закупочная цена плюс целая часть наценки; сумма строки: целая часть цены единицы × количества. Снимки старых заказов не пересчитываются. Тест money-boundaries проверяет значения выше Number.MAX_SAFE_INTEGER и согласованность итога с базой/наценкой.

## Перевод

Выбор ru/tg хранится в httpOnly SameSite cookie и передаётся через server layout в client context. Словарь интерфейса: `src/i18n/storefront.ts`, валидация локали: `src/i18n/locale.ts`. Добавляйте точные переводы исходных строк; неизвестная строка остаётся исходной и не переводится моделью на лету.

Переведены основные клиентские элементы навигации, формы входа/регистрации, адреса, корзина, оформление, создание заявки и основные состояния. Названия/описания товаров, расширенные технические характеристики, тексты из админки, юридические документы и PDF не объявляются полностью переведёнными. Админка остаётся русскоязычной. Для этих областей нужны отдельные контентные переводы и вычитка носителем.

## Расширенная приёмка кабинета и админки

`readiness.spec.ts` проверяет 9 маршрутов покупателя и 16 администратора, права гостя/покупателя, ссылки с соответствующей сессией, отсутствие горизонтального переполнения при 390 px и серьёзных/критических нарушений axe. Сценарий заказа проверяет создание, подтверждение администратором, обновление у покупателя и получение PDF. Фикстура включает заказ и КП; для каждого запуска сервера создаётся свежая база.

Добавлены 16 эталонов основных экранов (всего 19 с главной). Даты маскируются. Тайлы карты и Turnstile в этих визуальных сценариях замоканы; их внешняя доступность не проверяется снимками. Отдельный существующий сценарий проверяет совместимость Turnstile с CSP.

Быстрые команды после сборки: `npm run ui:check`, `npm run ui:links`, `npm run ui:visual`, `npm run smoke`. Полный выпуск: `npm run check:release`. Для повторяемого модульного прогона укажите новый PGLITE_DATA_DIR: старая тестовая база может содержать изменения прошлых сценариев; не используйте production DATABASE_URL. CI запускается с отдельной базой в чистом окружении.
