# Демонстрация StroySnab

## Подготовка

Основной адрес: https://www.stroysnab.tj. Используйте отдельный согласованный демонстрационный аккаунт. Пароли и API-ключи в этот документ не помещаются. На рабочем сайте оформление заказа резервирует реальные остатки и может отправить уведомления — для репетиции используйте локальные проверки.

## Сценарий показа

1. Главная на телефоне: компактная шапка, поиск, первый блок, товары 2×2 и «Показать ещё».
2. Каталог: поиск, категория, карточка, цена, количество, корзина. Публичного выбора поставщиков нет.
3. Покупатель: оформление самовывоза/доставки, наличные, просмотр заказа и PDF.
4. Кабинет: заказы, заявки, адреса и профиль; выбор точки на карте и ввод адреса вручную.
5. КП: загрузка списка, распознавание, точные соответствия/помеченные альтернативы, сумма из каталога, PDF с тёмно-синей палитрой и итогом слева. Нераспознанные позиции явно перечисляются отдельно.
6. Админка: каталог, наценка товара, внутренняя связь с поставщиком, заказ, смена статуса, заявки и КП, история цен.
7. Завершение: покупатель видит обновлённый статус; email и SMS проверяются раздельно, не обещайте доставку SMS до подтверждения Payom.

## Безопасная репетиция

`npm ci`, `npx playwright install chromium`, затем `npm run check:release`. Production-сборка проверяется на localhost:24130; для каждого прогона создаётся отдельная база acceptance. Фикстура включает покупателя, администратора, заказ и КП. Токены хранятся только в игнорируемом .data, внешние SMS/email/ИИ отключены. Не копируйте тестовые сессии в production.

## Перед клиентским показом

Проверьте основной www-адрес, вход сотрудника с кодом, наличие реальных товаров/остатков, фоновые сервисы, резервирование и актуальные контактные данные. Не выдавайте тестовую QR-заглушку в PDF за оплату. Корневой домен без www, реквизиты и вычитка перевода имеют отдельные незавершённые действия.
