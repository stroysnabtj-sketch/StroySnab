# Архитектура

Next.js App Router обслуживает публичную витрину, кабинеты и REST Route Handlers. Бизнес-операции размещены в `src/modules/*/service.ts`; страницы и обработчики только проверяют входные данные и вызывают сервисы.

Данные доступны через Drizzle ORM. В production используется PostgreSQL 15+ из `DATABASE_URL`; без этой переменной для локального предпросмотра запускается PGlite — встроенный PostgreSQL с файловым хранилищем `.data/kushoniyon`. Миграции общие. Расширения `pg_trgm`, `btree_gist`, `citext` подключены в обоих режимах.

Деньги хранятся как `bigint` в дирамах и сериализуются строками. Время хранится в UTC, отображается в Asia/Dushanbe. Тексты проходят через словари `src/i18n`, таджикская локаль использует русский откат.

## Каталог и цена

Одна карточка `products` связана с несколькими `supplier_offers`. Публичный сервис выбирает доступное предложение с минимальной итоговой ценой. Наценка вычисляется серверным `src/modules/pricing/service.ts` по приоритету `PRODUCT → SUPPLIER → CATEGORY → GLOBAL`; значения остаются в дирамах (`bigint`). Правила загружаются одним запросом на набор предложений.

Поиск совмещает `to_tsvector/plainto_tsquery`, `similarity` и `ILIKE`. Фильтрация по цене и наличию выполняется после серверного расчёта публичных предложений. Категории поддерживают иерархию с FK на родителя.

Изображения проходят через `StorageDriver`; локальная реализация хранит файлы вне публичной директории в `.data/storage`. В БД сохраняется ключ, не URL. Публичный обработчик отдаёт только файлы, связанные с `product_images`. Sharp проверяет формат, ограничивает пиксели, поворачивает по EXIF и создаёт оптимизированный WebP.

XLSX создаётся и читается как стандартный ZIP/XML-пакет через `fflate` и `fast-xml-parser`, без устаревших транзитивных зависимостей. CSV-экспорт нейтрализует формульные префиксы.
