# Дизайн и каталог — второй проход, 02.11.2026

Основание: пользователь поручил изменить первый экран, палитру, админку и дерево каталога, а также исправить характеристики в формах товара по трём файлам проекта.

## Изученные источники

- `Umnye_filtry_319_kategoriy.xlsx`: просмотрены все шесть листов, включая категории, 1 092 атрибута, правила и зависимости.
- `Bizon_TJ_derevo_kataloga.json`: программно сверены все 319 путей с листом «КАТЕГОРИИ». Расхождений путей нет.
- `Bizon_TJ_analiz_kataloga_i_TZ.md`: учтены границы экспертного справочника, различие групп и товаров, основные/дополнительные параметры и условные поля.

Файлы описывают экспертную модель, а не подтверждённые значения реального ассортимента. Примерные варианты не превращены в обязательный справочник наличия или искусственные значения товара.

## Реализация

- Главная получила новую композицию первого экрана с архитектурной SVG-иллюстрацией, крупным заголовком и отдельным блоком заявки. Палитра: глубокий зелёный, тёплая слоновая кость, медный акцент. Обновлены связанные элементы витрины и рабочего кабинета.
- Дерево админки раскрывается по уровням. Поиск показывает полный путь. Справа — выбранная группа, дочерние категории, типы характеристик, единицы и рекомендуемые поля. Прежние категории сохранены отдельно; привязки товаров автоматически не угадываются.
- В обеих формах товара есть поиск конечной группы и выбор полного пути. Родитель больше не получает фильтры первого ребёнка. Все 319 конечных групп связаны со своим профилем, основные/дополнительные поля и типы берутся из исходных файлов.
- Для применимых условных примеров реализовано переключение полей по виду изделия. Скрытые параметры другого вида исключаются при отправке формы, пользовательские дополнительные свойства сохраняются. Это не полный конструктор произвольных зависимостей и не движок технической совместимости оборудования.
- Сохранённые характеристики по русским названиям читаются рядом с прежними ключами. При изменении поля запись переводится на его ключ. Числа, логические свойства и текстовые значения имеют соответствующие контролы; примерные enum-значения не объявляются закрытым словарём.
- Исправлен возврат скрытой категории в админке: её API теперь включает неактивные категории, публичный каталог — по-прежнему активные.
- Добавлена пагинация админского списка товаров по 24 строки.
- `scripts/sync-catalog-taxonomy.ts`: отдельная синхронизация 395 узлов дерева (12 корней, промежуточные группы и 319 конечных групп). Без `--apply` выдаёт предварительный результат. В транзакции добавляет/обновляет только категории, сохраняет старые узлы и настройки видимости, не генерирует товары, цены, остатки и характеристики.

## Проверка и состояние базы

- TypeScript, ESLint и `npm run build:noenv` пройдены. Production-сборка проверена локально.
- Четыре E2E-сценария каталога прошли на production-сборке; динамические формы обеих ролей и адаптивная главная также повторно проверены на ней.
- Общий набор: 16 файлов, 109 тестов пройдены. После добавления исключения условных полей повторно пройдены три профильных теста.
- Браузер: главная на 360/390/1440 px; смена кирпича на гипсокартон в админке; исчезновение старых полей; мобильная форма на 390 px. Горизонтального переполнения в этих состояниях нет, pageerror не зафиксирован.
- Кабинет магазина: проверено появление напряжения аккумулятора при выборе шуруповёрта и исчезновение при выборе дрели.
- Снимки: `design-home-pine-*.png`, `design-taxonomy-1440.png`, `design-product-form-*.png`, `design-seller-form-1440.png`. Данные на снимках демонстрационные.

Основная локальная `.data/kushoniyon` по-прежнему падает с `PGlite RuntimeError: Aborted()` при открытии. Предварительный запуск синхронизации не смог открыть её. Создана отдельная копия `.data/recovery-design-2026-11-02`; попытка открыть копию без старого PID тоже не помогла. Исходные файлы базы сохранены. Причина сбоя не установлена; восстановление или перенос из проверенного дампа остаётся необходимым перед применением дерева к этой базе.

Предпросмотр и браузерные проверки используют `.data/design-2026-11-02`, куда загружен стандартный demo seed и безопасно добавлено дерево. Существующие demo-категории не удалены. Перенос живых товаров из старых категорий требует подтверждённой таблицы соответствий, особенно для смешанных групп; случайное назначение категории и выдуманные атрибуты не применялись.
